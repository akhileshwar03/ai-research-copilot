# Checker validation set

A small, real, labeled corpus for validating the AI Checker (and, later, any Tier 2
classifier signal) against genuine ground truth instead of one-off manual examples.

**Why this exists**: every fix made to `checker_service.py` on 2026-09-28/29 was verified
against a single hand-picked real-world example each time — which is how the false positive
and false negative were *found*, but is not a substitute for a real, structured evaluation
set that can be re-run after every future change. This is step one of that.

## Ground-truth design (no guessing, no hallucinating)

Three labeled categories, **topic-matched** so comparisons are apples-to-apples:

1. **`human`** — the first ~150-200 words of a real Wikipedia article, pinned to its
   **2013 revision** (`backend/scripts/finetune/pre2015_corpus/`, already gathered and
   verified for the humanizer's own fine-tuning work — reused here, not re-fetched). 2013
   predates GPT-3 (2020) and ChatGPT (2022) by years, so this text cannot be LLM-influenced,
   full stop. This is real, existing, already-vetted data, not a new claim.
2. **`ai_original`** — a fresh paragraph generated by calling the OpenAI API directly
   (`gpt-4.1-mini`, the same model the production Checker/Humanizer already use), asked for
   an ordinary informational paragraph on the **same topic** as the matching `human` sample,
   with a plain, realistic prompt — not deliberately stuffed with AI-tells. Genuinely,
   unambiguously AI-generated: we made the API call and have the raw response.
3. **`ai_humanized_basic`** — the `ai_original` sample run through the real, live Basic
   Humanizer (production API, same as any real user's request) — the actual, current
   production output, not a simulation.

## Files

- `build_validation_set.py` — builds `validation_set_v1.jsonl` from the steps above. Makes
  real OpenAI API calls (billed, ~8 short completions) and real production Humanizer calls
  (through the already-authenticated browser session's token, passed in as an env var —
  never hardcoded). Does **not** touch any database; reads `OPENAI_API_KEY` from
  `backend/.env` only for the OpenAI call.
- `validation_set_v1.jsonl` — the built dataset. One JSON object per line:
  `{"topic", "label", "text", "word_count", "source"}`.
- `run_validation.py` — runs every row in `validation_set_v1.jsonl` through the real
  production Checker API and prints a results table (per-label mean/median AI probability,
  verdict accuracy) plus the raw per-row results as JSON, so honest numbers are always
  re-derivable, never eyeballed from a summary alone.

## Running it

```bash
cd backend
venv/bin/python scripts/checker_eval/build_validation_set.py   # needs a fresh prod bearer token, see script
venv/bin/python scripts/checker_eval/run_validation.py
```
